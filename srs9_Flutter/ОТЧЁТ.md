# SRS 9 — Практическая работа: Launcher Icon, Unit Test, Widget Test

**Приложение:** «Мини-магазин» (`shop_app`): каталог товаров, корзина, подсчёт суммы, промокоды.

## Структура проекта

```
lib/
  main.dart                 — точка входа, ShopApp
  models/product.dart       — модель товара и каталог
  services/cart.dart        — логика корзины (тестируется Unit Test)
  screens/home_screen.dart  — главный экран (каталог)
  screens/cart_screen.dart  — экран корзины
assets/icon/
  app_icon.png              — собственная иконка 1024×1024
  app_icon_foreground.png   — передний слой для Adaptive Icon
test/
  cart_test.dart            — 9 Unit Test
  shop_widget_test.dart     — 5 Widget Test
```

## Задание 1. Launcher Icon

1. Нарисована своя иконка: белая тележка на зелёном фоне (тема магазина), PNG 1024×1024.
2. Иконка лежит в `assets/icon/`.
3. Пакет установлен командой `flutter pub add dev:flutter_launcher_icons`.
4. В конец `pubspec.yaml` добавлено:

```yaml
flutter_launcher_icons:
  android: true
  ios: true
  image_path: "assets/icon/app_icon.png"
  min_sdk_android: 21
  remove_alpha_ios: true
  adaptive_icon_background: "#2E7D32"
  adaptive_icon_foreground: "assets/icon/app_icon_foreground.png"
```

5. Иконки сгенерированы командой `dart run flutter_launcher_icons`.
6. Название приложения на телефоне изменено на «Мини-магазин» (`AndroidManifest.xml`).

## Задание 2. Unit Test (`test/cart_test.dart`)

Тестируется класс `Cart`, то есть логика корзины, без интерфейса. `setUp()` создаёт новую корзину перед каждым тестом.

| № | Тест | Что проверяет |
|---|------|---------------|
| 1 | Новая корзина пустая | 0 товаров, сумма 0 |
| 2 | Добавление товара | количество складывается (1 + 2 = 3) |
| 3 | Подсчёт стоимости | 2×450 + 120 = 1020 |
| 4 | Уменьшение и удаление | при количестве 0 товар исчезает из корзины |
| 5 | Верный промокод | `sale10` (с пробелами и строчными буквами) даёт скидку 10%: 900 → 810 |
| 6 | Неверный промокод* | `FREE100` отклоняется, сумма не меняется |
| 7 | Некорректное количество* | 0 и −3 вызывают `ArgumentError` |
| 8 | Уменьшение отсутствующего товара* | ошибки нет |
| 9 | Очистка корзины | товары и скидка сбрасываются |

\* проверка некорректных входных данных (дополнительное задание)

## Контрольные вопросы

1. **Что такое Launcher Icon?** Иконка приложения, которую видно на главном экране устройства и в списке установленных приложений.
2. **Для чего нужен пакет flutter_launcher_icons?** Он берёт одну картинку и сам создаёт иконки всех нужных размеров для Android (mipmap-*, adaptive icon) и iOS (AppIcon.appiconset), так что не нужно делать их вручную.
3. **В каком файле настраивается генерация иконки?** В `pubspec.yaml`, в разделе `flutter_launcher_icons:`.
4. **Что такое Unit Test?** Проверка отдельной функции, метода или класса (здесь класса `Cart`) отдельно от интерфейса.
5. **Чем Unit Test отличается от Widget Test?** Unit Test проверяет логику и результаты вычислений. Widget Test запускает виджеты в тестовой среде и проверяет, что отображается на экране и как интерфейс реагирует на действия пользователя (нажатия, ввод текста).
6. **Для чего нужна функция `expect()`?** Она сравнивает фактическое значение с ожидаемым (`expect(cart.total, 1020)`). Если значения не совпадают, тест падает.
7. **Какую роль выполняет `test()`?** Описывает один Unit Test: его название и код проверки.
8. **Для чего нужна `testWidgets()`?** Описывает Widget Test. Она передаёт объект `WidgetTester`, с помощью которого можно отрисовать виджет (`pumpWidget`), нажать (`tap`), ввести текст (`enterText`) и обновить кадр (`pump`, `pumpAndSettle`).
9. **Что делает команда `flutter test`?** Находит и запускает все тесты из папки `test/` и показывает, какие прошли, а какие нет.
10. **Почему важно тестировать приложение до публикации?** Так ошибки находятся до того, как их увидят пользователи. Кроме того, при изменении кода тесты сразу показывают, если что-то сломалось, а исправлять ошибку до релиза дешевле, чем после.
